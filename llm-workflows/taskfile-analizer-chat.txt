  ## Taskfile Structure Understanding

  - Tasks have `deps` (run in parallel) and `cmds` (run sequentially)
  - Commands can be shell scripts or task references
  - Files can include other taskfiles with namespacing
  - go-task prevents circular includes but allows task-level cycles

  ## Node Labeling Convention

  - Files named "Taskfile.yaml" or "taskfile.yaml" → use directory name as namespace
  - Files named "*.task.yaml" → use filename (without .task.yaml) as namespace  
  - Non-conforming files → use relative path from project root
  - Format: "namespace:taskname"
  - First encounter of a task determines its canonical label

  ## Execution Flow Representation

  Create temporary directory structure where:
  - Tasks = directories
  - Shell commands = files named "•" 
  - Parallel execution (deps) = same directory level
  - Sequential execution (cmds) = nested directories
  - Cycles = symlinks back to original task directory

  ## Cycle Detection

  - Track current execution path during traversal
  - When revisiting a task in current path → create symlink to original occurrence
  - Symlinks can span across different branches (cross-include cycles possible)

  ## Tools to Use

  - `yq` for YAML parsing (.tasks.taskname.deps[]?, .tasks.taskname.cmds[]?)
  - Standard bash for file operations and logic
  - `tree` command for final output
